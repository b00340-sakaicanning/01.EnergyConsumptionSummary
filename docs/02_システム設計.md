# 02. システム設計書 - 工場エネルギー（電力・燃料・トータルエネルギー）使用量集計システム

## 1. システムアーキテクチャ

本システムは、**「クライアント完結型ETL ＋ Google Apps Script（GAS）/スプレッドシート永続化」** のハイブリッド構成を採用している。

```mermaid
graph TD
    subgraph Client [クライアント環境: Webブラウザ (SPA)]
        A[ドラッグ＆ドロップ<br/>CSV/TXT/Excel/フォルダ] --> B[csvParser.js<br/>ヘッダー認識・kW抽出・外れ値補正]
        A --> C[excelReader.js<br/>SheetJS解析 (月報PET / 計算表)]
        B --> D[hourlyAggregator.js<br/>01分締め・2段階欠損補正]
        D --> E[categoryService.js<br/>11カテゴリ小計・操業時間集約]
        E & C --> F[kpiService.js<br/>操業3モード原単位・コスト算出]
        D & E --> G[annualService.js<br/>品種8分類年間集約・設備別集約]
        F & E & G --> H[charts.js / Table UI<br/>ダッシュボード可視化]
        I[Excelエクスポート<br/>SheetJS .xlsx]
    end

    subgraph Backend [Google Cloud / Workspace]
        D & E & F & G -->|google.script.run<br/>saveAggregatedData| J[GAS Code.gs]
        J -->|日時キー・年月キー照合 Upsert| K[(Googleスプレッドシート<br/>1時間集計(ALL) / 日別集約 / KPI評価 / 品種別集約)]
        K -->|loadSavedSummaryFromSpreadsheet<br/>起動時の復元| J
        K -->|getSheetsDataForExport| J
    end

    J -->|復元データ| H
    J -->|3シートの全データ| I
```

上の図は電力の処理の流れ。燃料エネルギーとトータルエネルギーは、Excel だけで表示する画面で、次のように処理する。
- **燃料エネルギー**: `excelReader.js` で読んだエネルギー計算表（A重油・LNG の熱量と購入費用）と月報PET（品種別本数）、および電力側で集計した品種別の操業時間を `fuelService.js` で集計し、`fuelView.js` が画面に表示する。保存先は `燃料集約` シート（`saveFuelMonthlyData`・`loadSavedFuelData`）。
- **トータルエネルギー**: `excelReader.js` で読んだエネルギー計算表（生産数量・熱量・原油換算量・CO2）を `totalEnergyService.js` で集計し、`totalEnergyView.js` が画面に表示する。保存先は `トータルエネルギー集約` シート（`saveTotalEnergyMonthlyData`・`loadSavedTotalEnergyData`）。
- どちらも、表示・保存の対象は月報PETに年度のシートがある年度だけ（4.4）。エクスポートは電力と共通で、5シートを出力する。

### アーキテクチャ上の重要設計判断
1. **GASの実行時間制限（6分）の完全回避**:
   - 1分値（月間約22万行）をGASへ直接送信すると、受信・パース・セル書き込みで制限時間を超過する。
   - そのため、ブラウザ側（JavaScript）で1時間値（744行）に集約・圧縮した上でGASに送信する構成とし、通信容量を99%削減。GAS側の書き込み処理は数秒で完了する。
2. **環境構築ゼロ・自己完結型バンドル**:
   - Python環境やNode.js等のインストールが一切不要。ブラウザを開いてファイルをドラッグ＆ドロップするだけで全機能が動作する。
   - `gas_app/build.js` により、CSSおよび全JSスクリプトを単一の `gas_app/index.html` に内包。GASへのコピー＆ペーストのみで本番稼働可能。
3. **ローカル開発対応**:
   - GASにデプロイせず、`gas_app/` をローカルサーバーで配信して `localhost` で開いても動作する。この場合、`google.script.run` が無いため、スプレッドシートへの反映は成功を返すだけのモック、Excelエクスポートはブラウザが保持しているデータから同じシート（電力の3シートと `燃料集約`・`トータルエネルギー集約`）を組み立てて出力する。
   - `localhost`（または `127.0.0.1`）で開いたときだけ、デモデータ（`demo/`）の読込ボタンが表示され、起動時に年間デモデータを自動で読み込む。

## 2. 画面構成設計 (SPA UI)

## 4. 処理フロー

### 4.1 通常の月次集計フロー
1. ユーザーが対象月のテキスト/CSVファイル群（月次ファイルまたは日別ファイル群・フォルダ）および外部Excel（月報PET、エネルギー計算表）をドロップゾーンへ投入。
2. `csvParser` がファイル名を判別し、測定盤ごとの有効電力列（kW）を動的に抽出。同時に、異常値（エラーコードや急激なスパイク）を直前有効値により補正。
3. `hourlyAggregator` が日時（XX:01〜(XX+1):00）ごとにグルーピングし、2段階欠損補正を適用して1時間平均（kWh）を算出。
4. `categoryService` が11カテゴリの小計および稼働時間を算出。
5. `kpiService` が生産本数および電気代単価と突き合わせ、原単位を計算。
6. `annualService` が8大品種および設備・工程カテゴリごとの月別数値を集約。
7. UI（KPIカード、Chart.jsグラフ、集計テーブル）に結果を描画。
8. 「スプレッドシートへ反映」ボタン押下により、`google.script.run.saveAggregatedData` を月ごとに1回ずつ呼び出し、スプレッドシートの4シート（`1時間集計(ALL)`、`日別集約`、`KPI評価`、`品種別集約`）に差分書き込み（Upsert）。対象は未反映の月のみ。読込済みの全月が反映済みの場合は、確認のうえ全月を上書きする。反映済みの月でも、ロガーファイルを読み直した場合と、Excel の投入で本数・電力量単価が変わった場合は、未反映に戻る。
9. 必要に応じて「Excelエクスポート」で、スプレッドシート上のシート（電力の3シートと `燃料集約`・`トータルエネルギー集約`）をローカルに保存。

### 4.2 起動時の復元フロー
1. アプリ起動時に `google.script.run.loadSavedSummaryFromSpreadsheet` を呼び出す。
2. GASが `KPI評価`・`日別集約`・`品種別集約` の3シートを読み、月ごとのサマリーを返す。
3. クライアントは返されたサマリーを月別データとして保持し、反映済みとして記録したうえで、年間ビューと単月ビューを描画する。
4. あわせて、GAS側 `Config.gs` の品種合算マッピング（`VARIETY_MAPPING`）と目盛り設定の初期値（`SCALE_CONFIG`）をクライアントへ反映する。

復元したデータには1時間値が含まれない。そのため、復元した月の品種別の値は `品種別集約` シートの保存値を使う。

### 4.3 Excelだけを後から投入した場合
CSV/TXTを含まず Excel だけを投入した場合は、読込済みの全月（スプレッドシートから復元した月を含む）について生産本数と電力量単価を取り直し、KPIと年間集約を再計算する。取り直すのは、投入済みの種類の Excel に由来する値だけで、もう一方の値はそのまま引き継ぐ。取得できなかった月がある場合は警告を表示する（`docs/03_データ設計.md` の 6.4）。

CSV/TXT と Excel を同時に投入した場合は、投入した CSV/TXT の月だけが対象になる（それ以外の読込済みの月は再計算しない）。

### 4.4 燃料エネルギー・トータルエネルギーの処理フロー

**表示・保存の対象にする年度**（両方の画面で共通）
- 読み込み済みの月報PETに年度のシートがある年度（`app.js` の `getPetFiscalYears`）。
- 月報PETを読み込んでいない場合は、スプレッドシートから復元したデータの年度（燃料エネルギーは品種別本数が保存されている年度、トータルエネルギーは保存されている年度）。
- 対象年度以外の復元データはメモリ上に残すが、表示・反映・未反映の件数には含めない。シート上の行も削除しない。

**燃料エネルギー**
1. Excel（エネルギー計算表・月報PET）が読み込まれると、`fuelView.js` が燃料の月次データ（月ごとの A重油・LNG の熱量と購入費用、8品種別の本数）を作り直す。Excel はどの画面から投入してもよい。燃料エネルギー・トータルエネルギーの画面から投入した場合も、電力の読込済みの月は 4.3 と同じように再計算する。
   - エネルギー計算表は、対象年度のシートを読み、熱量が入力されている月を対象にする。
   - 読み込んだ種類の Excel に由来する値だけを取り直し、もう一方の値は既存の値（スプレッドシートから復元した値を含む）を引き継ぐ。
2. `fuelService.js` が、月次データと、電力側の品種別の操業時間（水運転＋実充填）から、年度ごとの年間データセット（8評価項目の月別・品種別・累計・年間計）を作る。電力側のデータが変わったとき（ロガーデータの読込、起動時の復元、再計算）にも作り直す。
3. 燃料エネルギーの画面を表示しているときに、KPIカード・グラフ・集計表を描画する。
4. 「スプレッドシートへ反映」ボタン押下により、`google.script.run.saveFuelMonthlyData` を1回呼び出し、未反映の月（保存後に値が変わった月を含む）をまとめて `燃料集約` シートへ書き込む。全月が反映済みの場合は、確認のうえ全月を上書きする。
5. 起動時は `google.script.run.loadSavedFuelData` で `燃料集約` シートの値を復元し、反映済みとして記録する。

保存するのは月ごとの入力値（燃料の4値と品種別本数）だけで、按分後の値や原単位は表示のたびに計算する。操業時間は電力側のデータを使うため、燃料側では保存しない。

**トータルエネルギー**
1. Excel が読み込まれると、`totalEnergyView.js` が、対象年度のエネルギー計算表のシートから月次データ（生産数量、熱量、原油換算量、CO2、太陽光）を作り直す。月報PETは対象年度を決めるためだけに使う。
2. `totalEnergyService.js` が、年度ごとの年間データセット（月別の値と比、累計、年間計）と、年度推移・前年度比を作る。
3. トータルエネルギーの画面を表示しているときに、KPIカード・グラフ4つ・集計表・参考表を描画する。
4. 反映は `google.script.run.saveTotalEnergyMonthlyData`、起動時の復元は `google.script.run.loadSavedTotalEnergyData` で行う。未反映の判定・全月反映済みのときの確認は、燃料エネルギーと同じ。

GAS 側に燃料・トータルエネルギーの関数が無い場合（`index.html` だけを新しくし、`Code.gs` が古いままの場合）は、その画面の復元を行わず、反映時にエラーを表示する。他の画面の機能はそのまま動く。

---

## 5. API / インターフェース設計

クライアントとGASの通信は、すべて `google.script.run` によるサーバー関数の呼び出しで行う（HTTPの `doPost` は使用しない）。呼び出すのは次の7関数のみ（電力・燃料エネルギー・トータルエネルギーそれぞれの保存と復元、エクスポート用データの取得）。

### 5.1 `loadSavedSummaryFromSpreadsheet()`
- **引数**: なし
- **戻り値**:
```json
{
  "success": true,
  "savedYms": ["202410", "202503"],
  "monthlySummary": {
    "202503": {
      "ym": "202503",
      "catResult": {
        "categoryMonthlyTotals": { "総電力": { "grandTotal": 301066.4 }, "...": {} },
        "categoryDailyTotals": [ { "date": "2025/03/01", "day": 1, "categories": { "...": 0 }, "operationTimes": { "waterTimeMin": 0, "actualFillingMin": 0, "totalOperationMin": 0 } } ],
        "monthlyOperationTimes": { "waterTimeMin": 0, "actualFillingMin": 0 }
      },
      "kpiResult": { "electricitySummary": { "...": 0 }, "evaluation": { "combined": {}, "waterOnly": {}, "fillingOnly": {} } },
      "externalData": { "production": { "totalBottles": 0, "varieties": {} }, "electricity": { "unitPriceYenPerKwh": 0 } },
      "varietyAgg": { "combined": {}, "waterOnly": {}, "fillingOnly": {} }

- 失敗時は `{ "success": false, "error": "..." }`（スプレッドシートが見つからない場合は `message`）を返す。
- `KPI評価` シートには「水運転＋実充填」の値だけを保存しているため、復元した `kpiResult` の `fillingOnly` には同じ値が入り、`waterOnly` は 0 になる。

  "kpi": { "electricitySummary": { "unitPriceYenPerKwh": 21.4423 }, "evaluation": { "combined": { "totalKwh": 301066.4, "...": 0 } } },
  "varietyData": {
    "bottles": { "2.0L": 0, "...": 0 },

- **戻り値**:

  "yearMonth": "202503",
  "totalReceivedHours": 744,
  "updatedCount": 0,
  "appendedCount": 744

```

### 5.3 `getSheetsDataForExport()`
- **引数**: なし
- **戻り値**: `{ "success": true, "sheets": { "日別集約": [[...]], "KPI評価": [[...]], "品種別集約": [[...]], "燃料集約": [[...]], "トータルエネルギー集約": [[...]] } }`
- 各シートはヘッダー行を含む2次元配列。日付セルは `yyyy/MM/dd` の文字列に変換して返す。シートが無い場合は空配列。

### 5.4 `saveFuelMonthlyData(rows)`
- **引数**: 燃料の月次データの配列（複数月をまとめて渡す）。
  ```json
  [
    {
      "yearMonth": "202404",
      "heavyOilGj": 357.88,
      "lngGj": 5196.5,
      "heavyOilCostThousandYen": 1258.18,
      "lngCostThousandYen": 10629.26,
      "bottles": { "2.0L": 3200000, "1.5L": 478000 }
    }
  ]
  ```
  - `bottles` は8品種の本数。品種別本数が無い月は `null`（シート上は本数の8列が空欄になる）。
  - 燃料の値が `null` の項目は空欄として書き込む。
- **戻り値**: `{ "success": true, "savedCount": 12, "updatedCount": 2, "appendedCount": 10 }`。失敗時は `{ "success": false, "error": "..." }`。
- `燃料集約` シートが無ければ作成する。A列の対象年月が一致する行は上書きし、無ければ末尾へ追記する。`yearMonth` が6桁の数字でない行は無視する。

### 5.5 `loadSavedFuelData()`
- **引数**: なし
- **戻り値**: `{ "success": true, "months": { "202404": { "heavyOilGj": 357.88, "lngGj": 5196.5, "heavyOilCostThousandYen": 1258.18, "lngCostThousandYen": 10629.26, "bottles": { "2.0L": 3200000, ... } } } }`
- 空欄のセルは `null`。本数の8列がすべて空欄の月は `bottles` が `null`。`燃料集約` シートが無い場合は `months` が空のオブジェクトになる（シートは作成しない）。

### 5.6 `saveTotalEnergyMonthlyData(rows)`
- **引数**: トータルエネルギーの月次データの配列（複数月をまとめて渡す）。
  ```json
  [
    {
      "yearMonth": "202404",
      "productionCases": 907430.6,
      "litersPerCase": 12,
      "heavyOilGj": 357.88, "lngGj": 5196.5, "electricityGj": 2466.56, "totalGj": 8020.94,
      "crudeOilKl": 206.94,
      "heavyOilCo2": 25.33, "lngCo2": 264.85, "electricityCo2": 119.62, "totalCo2": 409.79,
      "solarKwhThousand": 20.06, "solarGj": 173.3, "solarCo2": 8.4, "noSolarCrudeOilKl": 211.4
    }
  ]
  ```
  - 項目は `Config.gs` の `TOTAL_ENERGY_SHEET_COLUMNS` の `key`。値が無い項目（`null`）は空欄として書き込む（太陽光の行が無い年度の太陽光の項目など）。
- **戻り値**: `{ "success": true, "savedCount": 12, "updatedCount": 2, "appendedCount": 10 }`。失敗時は `{ "success": false, "error": "..." }`。
- `トータルエネルギー集約` シートが無ければ作成する。上書き・追記の規則は 5.4 と同じ。

### 5.7 `loadSavedTotalEnergyData()`
- **引数**: なし
- **戻り値**: `{ "success": true, "months": { "202404": { "productionCases": 907430.6, "litersPerCase": 12, "heavyOilGj": 357.88, ... } } }`
- 空欄のセルは `null`。`トータルエネルギー集約` シートが無い場合は `months` が空のオブジェクトになる（シートは作成しない）。
