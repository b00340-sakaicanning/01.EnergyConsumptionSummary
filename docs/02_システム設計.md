# 02. システム設計書 - 工場エネルギー（電力）使用量集計システム

## 1. システムアーキテクチャ

本システムは、**「クライアント完結型ETL ＋ Google Apps Script（GAS）/スプレッドシート永続化」** のハイブリッド構成を採用している。

```mermaid
graph TD
    subgraph Client [クライアント環境: Webブラウザ (SPA)]
        A[ドラッグ＆ドロップ<br/>CSV/TXT/Excel/フォルダ] --> B[csvParser.js<br/>ヘッダー認識・kW抽出・外れ値補正]
        A --> C[excelReader.js<br/>SheetJS解析 (月報PET / 計算表)]
        B --> D[hourlyAggregator.js<br/>01分締め・2段階欠損補正]
        D --> E[categoryService.js<br/>6工程小計・操業時間集約]
        E & C --> F[kpiService.js<br/>操業3モード原単位・コスト算出]
        D & E --> G[annualService.js<br/>品種8分類年間集約・設備別集約]
        F & E & G --> H[charts.js / Table UI<br/>ダッシュボード可視化]
        D --> I[Excelエクスポート<br/>SheetJS .xlsx]
    end

    subgraph Backend [Google Cloud / Workspace]
        D & G -->|集約済みJSON POST| J[GAS Code.gs<br/>doPost API / doGet API]
        J -->|日時キー照合 Upsert| K[(Googleスプレッドシート<br/>1時間集計 / 日別集約 / KPI月次 / 品種別集約)]
        K -->|初期表示・復元データ取得| J
    end
```

### アーキテクチャ上の重要設計判断
1. **GASの実行時間制限（6分）の完全回避**:
   - 1分値（月間約22万行）をGASへ直接送信すると、受信・パース・セル書き込みで制限時間を超過する。
   - そのため、ブラウザ側（JavaScript）で1時間値（744行）に集約・圧縮した上でGASに送信する構成とし、通信容量を99%削減。GAS側の書き込み処理は数秒で完了する。
2. **環境構築ゼロ・自己完結型バンドル**:
   - Python環境やNode.js等のインストールが一切不要。ブラウザを開いてファイルをドラッグ＆ドロップするだけで全機能が動作する。
   - `gas_app/build.js` により、CSSおよび全JSスクリプトを単一の `gas_app/index.html` に内包。GASへのコピー＆ペーストのみで本番稼働可能。
3. **オフライン・ローカル利用対応**:
   - GAS環境だけでなく、ローカルのHTMLファイルとしても単独動作し、Excelエクスポート機能により社内ネットワーク内でのスタンドアロン利用も可能。
   - デモデータ（`demo/`）およびシミュレーション環境（`simulate/`）を分離整備し、オフライン検証も即座に実施可能。

## 2. 画面構成設計 (SPA UI)

### 2.1 画面レイアウト
- **ヘッダー**:
  - タイトル・ステータス表示
  - 年度選択セレクター（例: 2025年度、2024年度）
  - 単月年月セレクター（例: 2025年03月）
  - デモデータ読込ボタン（検証・プレビュー用）
  - Excelエクスポートボタン（.xlsxダウンロード）
  - スプレッドシートへ反映ボタン（GAS連携）
- **ファイル受付ゾーン (Dropzone)**:
  - ドラッグ＆ドロップ受付領域（日別生CSVフォルダ対応）
  - ファイル種別自動検知バッジ（tag02, tag04, tag05, tag06, tag07, かつらぎ計算表, 月報PET）
  - 進捗バー（プログレスインジケータ）
- **KPIサマリーカードグリッド**:
  - 年間/月間総電力量 (kWh)
  - 実充填操業時間 (時間)
  - 水運転時間 (時間)
  - 電力量単価 (円/kWh)
  - 電力原単位 (kWh/本)
- **タブ切り替えエリア**:
  - **タブ1: 年間推移（品種別）**:
    - 8品種積み上げバー ＋ 月計折れ線グラフ（年間電力集約グラフ）
    - 主要品種トレンド推移折れ線グラフ
    - 年間月別実績集計表（8大指標動的切り替え）
  - **タブ2: 年間推移（設備別）**:
    - 主要設備ごとの月別電力量推移折れ線グラフ
    - 設備別月別集計テーブル
  - **タブ3: 単月分析（グラフ・可視化）**:
    - 日別電力使用量推移（バーチャート＋7日間移動平均線）
    - 工程別小計電力比率（多層ドーナツチャート）
  - **タブ4: 単月日別集計テーブル**:
    - 日付、総電力、各工程小計、操業時間一覧
  - **タブ5: 1時間集計データプレビュー**:
    - 全90列の1時間値プレビューテーブル（横スクロール対応）

## 4. 処理フロー

### 4.1 通常の月次集計フロー
1. ユーザーが対象月のテキスト/CSVファイル群（月次ファイルまたは日別ファイル群・フォルダ）および外部Excel（月報PET、エネルギー計算表）をドロップゾーンへ投入。
2. `csvParser` がファイル名を判別し、測定盤ごとの有効電力列（kW）を動的に抽出。同時に、異常値（エラーコードや急激なスパイク）を直前有効値により補正。
3. `hourlyAggregator` が日時（XX:01〜(XX+1):00）ごとにグルーピングし、2段階欠損補正を適用して1時間平均（kWh）を算出。
4. `categoryService` が6大工程カテゴリの小計および稼働時間を算出。
5. `kpiService` が生産本数および電気代単価と突き合わせ、原単位を計算。
6. `annualService` が8大品種および主要設備ごとの月別数値を集約。
7. UI（KPIカード、Chart.jsグラフ、集計テーブル）に結果を瞬時に描画。
8. 「スプレッドシートへ反映」ボタン押下により、GAS `doPost` 経由でスプレッドシートの4シート（1時間集計、日別集約、KPI月次、品種別集約）に差分書き込み（Upsert）。
9. 必要に応じて「Excelエクスポート」でローカルに集計結果を保存。

## 5. API / インターフェース設計

### 5.1 GAS `doPost(e)` 仕様
- **リクエスト形式**: `POST` (Content-Type: `application/json` または `text/plain`)
- **ペイロード構造**:
```json
{
  "action": "syncHourlyData",
  "yearMonth": "202503",
  "rows": [
    {
      "timestampKey": "2025/03/01 01:00",
      "values": {
        "D": 13.5, "E": 12.0, "...": 0.0, "CO": 4.2
      }
    }
  ],
  "categoryDaily": [ ... ],
  "categoryMonthly": { ... },
  "kpi": { ... },
  "varietyData": { ... }
}
```
- **レスポンス形式**:
```json
{
  "success": true,
  "updatedRows": 744,
  "insertedRows": 0,
  "message": "スプレッドシートへの同期が正常に完了しました。"
}
```
