# 04. 実装仕様書 - 工場エネルギー（電力・燃料）使用量集計システム

## 1. コア計算ロジック仕様

### 1.1 01分締め（XX:01〜(XX+1):00）集約ロジック
工場の電力ロガー仕様に基づき、各時間帯の集計枠は **毎時01分から翌時00分までの60分間** とする。集計枠の日時キーは、枠の開始時刻の「時」で表す。

```
【例: 日時キー 2025/03/01 00:00 の集計対象範囲】
開始: 2025/03/01 00:01:00
終了: 2025/03/01 01:00:00
サンプル数: 最大60件
```

- **1分値の振り分け**:
  - `HH:00:00` の1分値は、直前の時間枠に含める（例: `01:00:00` → 0時台）。
  - `00:00:00` の1分値は、前日の23時台に含める。月初1日の `00:00:00` は前月分にあたるため、当月の集計には使わない。
  - それ以外（`HH:01`〜`HH:59`）は、その時刻の「時」の枠に含める。
- 1か月分の枠数は「その月の日数 × 24」（31日の月で744）。

### 1.2 2段階欠損補正ロジック

Excel原紙との突合で一致させるための欠損値処理。

#### (1) 短時間欠損（1時間枠内での部分欠損）
- 1時間枠内（最大60サンプル）のうち、有効な測定値が存在する場合：
  $$\text{HourlyValue} = \text{ROUND}\left(\frac{\sum_{i=1}^{N} \text{Sample}_i}{N}, 1\right)$$
  - $N$: 当該時間枠内の有効サンプル数（$1 \le N \le 60$）
  - 丸め処理: 小数第1位に四捨五入（Excelの `ROUND(AVERAGE(...), 1)` に相当）
- kW の1分値の平均を、そのまま1時間あたりの電力量（kWh）として扱う。

#### (2) 長時間欠損（1時間以上の連続欠損・停電）
- 1時間枠内のサンプル数が 0 の場合：
  - 直前の有効な時間枠の値をそのまま引き継ぎ、その行に補間フラグを立てる。
  - 直前の有効な時間枠が無い場合（月初など）は `0.0` とする。
- 1時間枠にサンプルはあるが、ある列だけ有効値が1件も無い場合（該当タグのファイルが無い場合など）も、その列は直前の有効な時間枠の値、無ければ `0.0` とする。この場合は補間フラグを立てない。

#### (3) 月末23:59パディング補正
- 月末最終日の23時台のサンプルがちょうど59件の場合（ロガーデータが `23:59:00` で終了している場合）、最後の1分値を複製して60件目とし、最終時間枠を集約する。

#### (4) 固定値の列
- M列（消火ﾎﾟﾝﾌﾟ盤）と CB列（2F 低圧動力盤 №5 HGINV）は、ロガーデータに関係なく常に `0.0` とする（`js/config.js` の `fixedVal`）。

### 1.3 センサー異常値・外れ値自動補正ロジック
工場ロガーの通信途絶、センサー断線、オーバーレンジによる極端な異常値（例: `21,000,000 kW`）が集計値を壊さないよう、1分値の取り込み時に補正する。

- **判定基準**:
  1. **絶対上限値超過**: $\text{val} \ge 1,000\text{ kW}$
  2. **急激な異常スパイク**: $|\text{val} - \text{lastValidValue}| > 500\text{ kW}$（直前有効値との差分が500kW超）
- **補正処理**:
  - いずれかに該当した場合、その1分値は使わず、**直前の有効測定値（`lastValidValue`）を採用**する（直前値が無い場合は `0.0`）。
  - 直前の有効測定値は、ファイル（1日分）ごと・列ごとに保持する。

## 2. KPI・原単位算出仕様

### 2.1 操業3モード分類

| モード | 操業モード名称 | 対象操業時間 | 考慮するステップ大分類 |
|:---:|:---|:---:|:---|
| `combined` | **水運転＋実充填** | $T_w + T_f$ | 20（水運転）＋ 30（実充填） |
| `waterOnly` | **水運転のみ** | $T_w$ | 20（水運転） |
| `fillingOnly` | **実充填のみ** | $T_f$ | 30（実充填） |

### 2.2 月次KPIの計算式（`KpiService.calculateKpi`）

- **モード別の電力量**:
  - 水運転＋実充填: 月間の総電力量。
  - 水運転のみ／実充填のみ: 総電力量を操業時間の比で按分する。
    $$\text{水運転の電力量} = \text{総電力量} \times \frac{T_w}{T_w + T_f} \qquad \text{実充填の電力量} = \text{総電力量} \times \frac{T_f}{T_w + T_f}$$
- **単位時間電力量 (kWh/分)**: $\text{電力量} \div \text{操業時間（分）}$（小数第3位まで）
- **原単位 (kWh/本)**: $\text{電力量} \div \text{総生産本数}$（小数第4位まで）
- **コスト原単位 (円/本)**: $\text{原単位 (kWh/本)} \times \text{電力量単価 (円/kWh)}$（小数第2位まで）
- 「水運転のみ」は生産本数を 0 として扱うため、kWh/本 と 円/本 は 0 になる。
- 電力量単価はエネルギー計算表から取得する（`金額（千円） ÷ 使用電力量（千kWh）`）。取得できない場合は既定の単価を使う。
- 月報PETから本数を取得できない月（対象年度のシートが無い、または未入力）は、生産本数を 0 として扱う。このとき kWh/本 と 円/本 は 0 になる。

### 2.3 品種別の集計（`AnnualService.aggregateMonthByVariety`）

1. 1時間ごとに、その時間内で最も多く記録された品種コードから8大分類を決める。
2. 水運転または実充填が1分でもあった時間について、その時間の総電力量（総電力カテゴリの列合計）を、その品種の「水運転＋実充填」に計上する。操業が全く無かった時間の電力は、どの品種にも計上しない。
3. 「水運転のみ」「実充填のみ」には、その時間の総電力量を水運転・実充填の分数の比で按分して計上する。

このため、年間・品種別ビューの「年間総電力量」（操業のあった時間の電力量の合計）は、年間・設備別ビューの「年間総電力量」（全時間の総電力カテゴリの合計）より小さくなる。

### 2.4 年間集計（`AnnualService.buildAnnualDataset`）

- 年度は4月〜翌3月。3つの操業モードそれぞれについて、次の8指標を月別・品種別に算出する。

| 指標キー | 名称 | 単位 | 算出 |
|---|---|:---:|---|
| `powerKwh` | 電力量 | kWh | 品種別の電力量の合計 |
| `operationMin` | 操業時間 | 分 | 品種別の操業時間の合計 |
| `productionBottles` | 生産本数 | 本 | 月報PETの本数（「水運転のみ」は 0） |
| `kwhPerBottle` | 単位本電力量 | kWh/本 | 電力量 ÷ 生産本数 |
| `kwhPerMinute` | 単位時間電力量 | kWh/分 | 電力量 ÷ 操業時間 |
| `powerCostYen` | 電力コスト | 円 | 電力量 × 電力量単価 |
| `costPerBottle` | 単位本コスト | 円/本 | 電力コスト ÷ 生産本数 |
| `costPerMinute` | 単位時間コスト | 円/分 | 電力コスト ÷ 操業時間 |

- データの無い月は空欄（`hasData = false`）とし、累計・年間計には含めない。
- 「累計」は、総量系の4指標（電力量、操業時間、生産本数、電力コスト）では4月からの積み上げ値。原単位系の4指標（`AppConfig.RATE_METRIC_KEYS`）では、現状は当月の値をそのまま表示している。
- 1時間値を持つ月（ファイルを読み込んだ月）は 2.3 の方法で品種別に集計し、スプレッドシートから復元した月は `品種別集約` シートの保存値を使う。
- 品種別の電力量・操業時間がすべて 0 の月は、月の総電力量（総電力カテゴリの月間合計）と操業時間を使い、月報PETの品種別本数の比で各品種に按分する。
- 電力量単価が無い月は 20.0 円/kWh として電力コストを計算する。
- あわせて、設備・工程カテゴリごとの月別値と年間計（年間・設備別ビュー用）を作る。

### 2.5 グラフ目盛り上限の決め方（`app.js` の `getScaleOptions`）

目盛り設定が「自動」のときは、読込済みの**全年度**のデータ（品種別グラフは選択中の操業モード）の最大値から上限を決める。年度を切り替えても目盛りが変わらないようにするためで、値の小さい年度ではグラフが相対的に低く表示される。

| グラフ | 自動のときの上限 | 固定値のときの上限 |
|---|---|---|
| 月別電力使用量集約グラフ（総量系・積み上げ） | `getNiceMax(8品種の月計の最大)`。電力量は設備別グラフと共通の上限 | 目盛り設定の値 |
| 月別電力使用量集約グラフ（原単位系）の棒（左軸） | `getAxisMaxForPeak(品種単体の最大, rateBarPeakRatio)` | 目盛り設定の値 |
| 同グラフの全体平均の折れ線（右軸） | `getAxisMaxForPeak(全体平均の最大, rateLinePeakRatio)` | 目盛り設定の値 × 0.6 |
| 月別電力使用量推移（総量系） | `getAxisMaxForPeak(品種単体の最大, trendPeakRatio)` | 自動と同じ（入力欄が無いため、常にデータから算出する） |
| 月別電力使用量推移（原単位系） | Chart.js の自動 | Chart.js の自動 |
| 月別設備別・工程別電力推移 | `getNiceMax(設備総電力の月最大と、品種月計の最大の大きい方)` | 目盛り設定の値 |
| 日別電力使用量推移 | `getNiceMax(日別総電力の最大)` | 目盛り設定の値 |

- `getNiceMax(val)`: 値の 1.08 倍を、切りの良い値へ切り上げる。
- `getAxisMaxForPeak(peakValue, peakRatio)`: 「データの最大値が軸の高さの `peakRatio` の位置に来る」上限（`peakValue ÷ peakRatio`）を、切りの良い値へ切り上げる。切り上げの候補は `getNiceMax` より細かく、データの最大値は狙った高さの 0.8〜1.0 倍の位置に収まる（`peakRatio` が 0.6 なら軸の 48〜60%、0.9 なら 72〜90%）。候補は Chart.js の目盛り間隔で割り切れる値だけにしてあり、目盛りは等間隔になる。
- 高さの目安は `SCALE_CONFIG.autoLayout`（`js/config.js` と `Config.gs` の両方）で調整する。原単位系の集約グラフは、棒（左軸）と折れ線（右軸）が別々の軸を持つため、棒を軸の中ほど（`rateBarPeakRatio` = 0.6）、折れ線を上部（`rateLinePeakRatio` = 0.9）に置いて、棒を大きく見せつつ折れ線と重なりにくくしている。`rateBarPeakRatio` を大きくすると棒は高くなるが、全体平均が低い月の折れ線と重なりやすくなる。
- 燃料エネルギーのグラフは、常に自動で上限を決める（目盛り設定の対象外）。読込済みの全年度の最大値を使う点と、高さの目安（`autoLayout`）は電力と同じ。総量系の集約グラフは `getNiceMax(月計の最大)`、推移グラフは `getAxisMaxForPeak(品種単体の最大, trendPeakRatio)`、原単位系の集約グラフは棒が `getAxisMaxForPeak(品種単体の最大, rateBarPeakRatio)`、折れ線が `getAxisMaxForPeak(全体平均の最大, rateLinePeakRatio)`（`FuelView.computeScale`）。

### 2.6 燃料エネルギーの計算（`FuelService.buildFuelAnnualDataset`）

参考: `月別燃料エネルギー使用量集約グラフ表示(2024).xlsx`。燃料は A重油と LNG の合算で扱う。

**月の値**
- 燃料エネルギー（MJ）= （A重油の熱量GJ ＋ LNG の熱量GJ）× 1000
- 燃料コスト（円）= （A重油の購入費用 千円 ＋ LNG の購入費用 千円）× 1000
- 燃料単価（円/MJ）= 燃料コスト ÷ 燃料エネルギー
- 熱量の合計が 0 より大きい月を「データあり」とする。

**品種別への按分**
- 品種の液量 = 本数 × 1本あたりの容量（`AppConfig.VARIETY_GROUPS[].capacityL`。2.0L=2.0、1.5L=1.5、1.0L=1.0、600mL丸=0.6、500mL丸=0.5、500mL角=0.5、350mL=0.35、280mL=0.28）
- 品種別の燃料エネルギー = 月の燃料エネルギー × 品種の液量 ÷ 全品種の液量の合計
- 品種別のコスト = 燃料単価 × 品種別の燃料エネルギー

**8評価項目**（`AppConfig.FUEL_METRICS`）

| キー | 評価項目 | 単位 | 品種別の値 | 月計 |
|---|---|---|---|---|
| `fuelMj` | 燃料エネルギー | MJ | 按分した値 | 月の燃料エネルギー |
| `operationMin` | 操業時間 | 分 | 電力側の品種別の操業時間（水運転＋実充填） | 品種別の合計 |
| `productionBottles` | 生産本数 | 本 | 月報PETの品種別本数 | 品種別の合計 |
| `mjPerBottle` | 単位本燃料エネルギー | MJ/本 | 品種別MJ ÷ 品種別本数 | 月のMJ ÷ 本数の合計 |
| `mjPerMinute` | 単位時間燃料エネルギー | MJ/分 | 品種別MJ ÷ 品種別操業時間 | 月のMJ ÷ 操業時間の合計 |
| `fuelCostYen` | 燃料エネルギーコスト | 円 | 燃料単価 × 品種別MJ | 月の燃料コスト |
| `costPerBottle` | 単位本コスト | 円/本 | 品種別コスト ÷ 品種別本数 | 月のコスト ÷ 本数の合計 |
| `costPerMinute` | 単位時間コスト | 円/分 | 品種別コスト ÷ 品種別操業時間 | 月のコスト ÷ 操業時間の合計 |

- 単位時間の2項目は、電力の画面に合わせて1分あたりで表示する。参考 Excel は1時間あたりのため、数値は参考 Excel の 1/60 になる。
- 分母が 0 の品種は 0 とする。

**累計・年間計**
- 総量系（燃料エネルギー、操業時間、生産本数、コスト）: 月の値を積み上げる。
- 原単位系（`isRate` が `true` の4項目）: 累計どうし・年間計どうしの比とする（月の値の平均ではない）。その項目のデータがある月だけを分子・分母に含める。

**値が無い月の扱い**

| 状況 | 表示 |
|---|---|
| 品種別の本数が無い月 | 燃料エネルギー・コストは月計のみ（品種別は値なし）。生産本数・単位本燃料エネルギー・単位本コストはデータなし |
| 操業時間が無い月（電力側にその月のデータが無い、または操業時間の合計が 0） | 操業時間・単位時間燃料エネルギー・単位時間コストはデータなし |

集計表では値なしを「---」と表示する。総量系の集約グラフでは、品種別の内訳が無い月の月計を、灰色の棒（「月計 (品種内訳なし)」）で表示する。

## 3. クライアント側主要モジュール仕様

読み込み順は `config.js` → `etl/*` → `services/*` → `components/charts.js` → `fuelView.js` → `app.js`。各モジュールはブラウザではグローバル変数として、Node.js では `module.exports` として使える（`tests/` から利用）。

### 3.1 `AppConfig` (`gas_app/js/config.js`)
マスターと共通定数。

| 名前 | 内容 |
|---|---|
| `VARIETY_MASTER` / `VARIETY_GROUPS` / `VARIETY_KEYS` | 品種マスター、8大分類（該当コード・識別色）、8大分類キーの並び |
| `VARIETY_MAPPING` | 月報PETの品種見出しを8大分類に合算するためのキーワード。起動時に GAS 側 `Config.gs` の値で上書きされる |
| `EVALUATION_METRICS` / `RATE_METRIC_KEYS` | 8指標の定義（名称・単位・小数桁）、原単位系の指標キー |
| `FUEL_METRICS` | 燃料エネルギーの8評価項目の定義（キー・名称・単位・小数桁・原単位系かどうかの `isRate`） |
| `FISCAL_MONTH_ORDER` / `FISCAL_MONTH_LABELS` / `getFiscalYear(year, month)` | 年度の月の並び（4月〜3月）とラベル、年度判定 |

| `SCALE_CONFIG` | グラフ目盛り設定の初期値（`mode`、`fixedValues`）と、自動算出時の高さの目安（`autoLayout`） |

`VARIETY_KEYS`（GAS側は `VARIETY_KEYS` として直接定義）、`VARIETY_MAPPING`、`CATEGORIES`、設備90列、`SCALE_CONFIG` は `Config.gs` にも同じ定義があり、両方を一致させる必要がある（`tests/verify_config_sync.js` で検証）。

### 3.2 `CsvParser` (`gas_app/js/etl/csvParser.js`)
- `detectTagType(fileName, firstFewLines)`: ファイル名（`tag02` などの文字列、または `_002` などの末尾）からタグを判別する。判別できない場合は、先頭5行の `収集タグNo.` から判別する。
- `parseSingleFile(fileContent, fileName)`: 1ファイルを解析する。先頭25行から `名称` 行・`単位` 行・データ開始行を探し、単位が `kW` の列だけを設備列に割り当て、外れ値を補正する。3つの行が揃わないファイルは対象外（`null`）。
- `parseCsvLine(line)`: カンマ区切り1行の分解（ダブルクォート対応）。
- `mergeTagFiles(files)`: 複数ファイルをタイムスタンプで横持ち結合する。同じタイムスタンプ・同じ列の値は、後から処理したファイルの値で上書きする。
- `groupFilesByYearMonth(files)`: ファイル名に含まれる `YYYYMM`（無ければ本文先頭の日付）で、年月ごとにファイルをグループ化する。

### 3.3 `HourlyAggregator` (`gas_app/js/etl/hourlyAggregator.js`)
- `aggregateHourly(mergedRecords, yearMonth)`: 01分締めの振り分け、1時間平均、欠損補正、月末パディングを行い、1か月分の1時間行を生成する。
  - 戻り値: `{ yearMonth, totalHours, columnKeys, rows, monthlyColumnSums }`
  - 各行: `{ hourIndex, timestampKey, date, hour, isInterpolated, varietyCode, values, operationTimes: { waterTimeMin, actualFillingMin } }`

### 3.4 `CategoryService` (`gas_app/js/services/categoryService.js`)
- `aggregateCategories(hourlyRows, monthlyColumnSums)`: 11カテゴリの日別小計・月間合計と、操業時間の合計を算出する。
  - 戻り値: `{ categoryDailyTotals, categoryMonthlyTotals, monthlyOperationTimes }`

### 3.5 `KpiService` (`gas_app/js/services/kpiService.js`)
- `calculateKpi(categoryMonthlyTotals, monthlyOperationTimes, productionData, electricityData)`: 操業3モードごとの KPI を算出する（2.2）。
  - 戻り値: `{ electricitySummary, evaluation: { combined, waterOnly, fillingOnly } }`

### 3.6 `AnnualService` (`gas_app/js/services/annualService.js`)
- `aggregateMonthByVariety(hourlyRows)`: 1か月分の1時間行から、品種×操業モード別の電力量・操業時間を集計する（2.3）。
- `buildAnnualDataset(fiscalYear, monthlyDatasets)`: 月別データ群から、年度の年間データセット（3モード×8指標の月別・品種別・累計・年間計、設備別の月別値）を構築する（2.4）。
- `getFiscalMonths(fiscalYear)`、`matchVarietyGroup(code)`、`createEmptyAnnualDataset(fiscalYear)`: 上記の補助関数。

### 3.7 `ExcelReader` (`gas_app/js/etl/excelReader.js`)
- `parsePetMonthlyReport(buffer, yearMonth)`: 月報PETから、対象月の総生産本数と8大分類別の本数を抽出する。戻り値は `{ yearMonth, totalBottles, varieties, sheetFound }`。
- `parseEnergyCalculationTable(buffer, yearMonth)`: エネルギー計算表から、対象月の使用電力量・金額・電力量単価を抽出する。戻り値は `{ yearMonth, usedKwhThousand, costThousandYen, unitPriceYenPerKwh, sheetFound }`。
- どちらも、対象年度のシートだけを読む。シートが無い場合は `sheetFound` が `false` になり、値は 0 または `null` を返す（別の年度のシートや先頭のシートでは代用しない）。対象月が未入力の場合は、`sheetFound` が `true` のまま値が 0 または `null` になる。
- `parseFuelEnergyTable(workbook, fiscalYear)`: エネルギー計算表の年度シートから、12か月分の燃料の4値（A重油・LNG の熱量GJと購入費用千円）を抽出する。戻り値は `{ fiscalYear, sheetFound, layoutFound, months: { [ym]: { heavyOilGj, lngGj, heavyOilCostThousandYen, lngCostThousandYen } } }`。空欄のセルは `null`。月見出しの行や燃料の行を特定できない場合は `layoutFound` が `false` になる。

読み取る位置の詳細は `docs/03_データ設計.md` の「6. 入力ファイル設計」を参照。

### 3.8 `ChartManager` (`gas_app/js/components/charts.js`)
- `renderAnnualStackedBarChart` / `renderAnnualTrendChart`: 年間・品種別ビューの2グラフ。燃料エネルギーの画面でも同じ関数を使う。グラフのインスタンスは canvas ごとに持つ。原単位系かどうかは、指標定義に `isRate` があればその値、無ければ `AppConfig.RATE_METRIC_KEYS` で判定する。
- `renderAnnualEquipmentTrendChart` / `renderAnnualEquipmentDoughnutChart`: 年間・設備別ビューの2グラフ。
- `renderDailyChart` / `renderCategoryDoughnutChart`: 単月詳細ビューの2グラフ。
- `getNiceMax(val)` / `getAxisMaxForPeak(peakValue, peakRatio)`: 目盛り上限用に、値を切りの良い数値へ切り上げる（使い分けは 2.5）。
- 工程大分類5種とユーティリティ内訳5種の名前・色は `MAIN_PROCESSES`・`UTILITY_BREAKDOWN` に、積み上げ棒の系列定義は `buildStackedBar()` に、2重ドーナツの設定は `buildProcessDoughnutConfig()` にまとめている。品種の色は `AppConfig.VARIETY_GROUPS` から生成する。

### 3.9 `app.js` (`gas_app/js/app.js`)
画面制御と各モジュールの連携を行う。

| 関数 | 役割 |
|---|---|
| `initApp` | 初期化。イベント登録、ローカル開発判定、燃料エネルギーの画面の初期化、起動時の復元を行う |
| `switchApp` | 電力と燃料エネルギーの切り替え。ナビゲーション・各ビュー・ヘッダーのボタン・副題・同期状況の表示を切り替える |
| `restoreSavedDataFromSpreadsheet` | スプレッドシートの保存データを復元する（ローカル開発時は年間デモデータを読み込む） |
| `handleFiles` | 電力の画面に投入されたファイルを TXT/CSV と Excel に分けて読み込む |
| `loadExcelFiles` / `applyExcelToLoadedMonths` | Excel の読み込みと、電力の読込済みの月への反映。電力・燃料エネルギーの両方の投入口から使う |
| `handleFuelFiles` | 燃料エネルギーの画面に投入されたファイルの処理（Excel のみ受け付ける） |
| `getOperationMinutesByYm` | 電力の読込済みの月から、品種別の操業時間（水運転＋実充填）を取り出す。燃料エネルギーの操業時間系の項目に使う |

| `detectExcelKind` / `extractExternalDataForMonth` | Excel の種別判定と、対象月の生産本数・電力量単価の抽出。取得できなかった理由（年度のシートなし／未入力）も返す。その種類の Excel が未読込なら、その月の既存の値を引き継ぐ（`docs/03_データ設計.md` の 6.4） |

| `recalculateAllLoadedMonths` | Excel だけを後から投入したときに、読込済み全月の KPI を再計算する。保存される値（本数・単価）が変わった月は未反映に戻す |
| `rebuildAnnualDataFromMonthlyDatasets` | 月別データから年度ごとの年間データセットを作り直す |
| `renderAnnualView` / `renderAnnualEquipmentView` / `renderSingleMonthData` | 電力の3ビューの描画 |
| `renderAnnualTable` | 年間月別実績集計表の描画。出力先・月の並び・値なしの表示方法を引数で受け取り、燃料エネルギーの集計表でも使う |

### 3.10 `FuelService` (`gas_app/js/services/fuelService.js`)
燃料エネルギーの集計（2.6）。

- `summarizeFuelMonth(monthInput)`: 1か月分の燃料の4値から、熱量の合計・燃料エネルギー（MJ）・コスト・燃料単価と、データの有無を求める。
- `allocateByLiquidVolume(totalMj, bottles)`: 月の燃料エネルギーを、液量の比で8品種に按分する。
- `buildFuelAnnualDataset(fiscalYear, fuelMonthly, operationMinByYm)`: 年度の年間データセットを作る。戻り値は `{ fiscalYear, months, monthLabels, availableMonthsCount, metrics, breakdown, breakdownTotal }`。`metrics[キー]` は電力の年間データと同じ形（`{ months: { [ym]: { hasData, monthlyTotal, cumulativeTotal, varieties } }, annualTotal }`）で、グラフと集計表を電力と共用できる。`breakdown` は燃料別の熱量・費用の表に使う。

### 3.11 `FuelView` (`gas_app/js/fuelView.js`)
燃料エネルギーの画面の制御。通知・数値の整形・集計表の描画などの共通の部品は、`app.js` が `init()` に渡す。

| 関数 | 役割 |
|---|---|
| `init(dependencies)` | 初期化。評価項目・年度の選択、投入口のイベント登録、起動時の復元を行う |
| `mergeFuelMonthly(existing, energyWorkbooks, petWorkbooks)` | 読み込み済みの Excel から、燃料の月次データを作り直す。読み込んだ種類の値だけを取り直し、読み込んでいない種類の値は既存の値を引き継ぐ。読めなかった年度・月報PETにシートが無い年度も返す |
| `buildAnnualDatasets(monthly, operationMinByYm)` | データのある年度ごとに、`FuelService.buildFuelAnnualDataset` で年間データセットを作る |
| `onExcelFilesChanged(notify)` / `onOperationDataChanged()` | Excel が読み込まれたとき／電力側のデータが変わったときに、`app.js` から呼ばれる |
| `render()` | KPIカード、グラフ、集計表、燃料別の表を描画する |
| `computeScale` / `buildTotalOnlySeries` | グラフの目盛り上限（2.5）と、品種別の内訳が無い月の月計の棒 |
| `monthSignature(month)` | 保存する値（燃料の4値と品種別本数）を比較用の文字列にする。保存済みの値と違う月を未反映として扱う |
| `updateSyncStatusUI()` / `handleSync()` | 同期状況の表示と、スプレッドシートへの反映（`saveFuelMonthlyData`） |
| `buildExportRows()` | ローカル開発時のエクスポート用に、`燃料集約` シートと同じ形の行を作る |

`mergeFuelMonthly`・`buildAnnualDatasets`・`monthSignature` などのデータ処理は DOM を使わないため、Node.js のテスト（`tests/verify_fuel_view.js`）から利用できる。

## 4. バックエンド仕様 (`gas_app/Code.gs`)

### 4.1 `doGet(e)`
- SPAアプリケーションのHTML（`index.html`）を返却する。

### 4.2 クライアントから呼び出す関数
`google.script.run` 経由で呼び出す。引数と戻り値の形は `docs/02_システム設計.md` の「5. API / インターフェース設計」を参照。

- `loadSavedSummaryFromSpreadsheet()`: `KPI評価`・`日別集約`・`品種別集約` の3シートを読み、月ごとの復元用サマリーを返す。
- `saveAggregatedData(payload)`: 1か月分の集約データを4シートへ書き込む。
- `getSheetsDataForExport()`: `日別集約`・`KPI評価`・`品種別集約`・`燃料集約` の全データを返す。
- `saveFuelMonthlyData(rows)`: 燃料の月次データ（複数月）を `燃料集約` シートへ書き込む。
- `loadSavedFuelData()`: `燃料集約` シートを読み、月ごとの燃料の値と品種別本数を返す。

燃料の2関数は、電力の `saveAggregatedData`・`loadSavedSummaryFromSpreadsheet` とは独立している（互いのシートを読み書きしない）。

### 4.3 内部関数
| 関数 | 役割 |
|---|---|
| `setupSheets(ss)` | 5シート（電力の4シートと `燃料集約`）が無ければ作成し、ヘッダーを設定する。`saveAggregatedData` の冒頭で毎回呼ぶほか、GASエディタから手動でも実行できる |
| `setupFuelSheet(ss)` / `getFuelSheetName()` / `getFuelSheetHeader()` | `燃料集約` シートの取得（無ければ作成）、シート名、ヘッダー（13列） |
| `getSpreadsheet()` | `CONFIG.SPREADSHEET_ID` があればそのスプレッドシートを、空ならスクリプトが紐づくスプレッドシートを返す |
| `saveDailySummary` / `saveKpiSummary` / `saveVarietySummary` | 各シートへ書き込む行を組み立てる |
| `writeMonthBlock(sheet, rows, yearMonth)` | 1か月分の行をまとめて書き込む（既存月は上書き、無ければ追記）。`1時間集計(ALL)` と `日別集約` で使用 |
| `upsertRowByYearMonth(sheet, yearMonth, newRow)` | 対象年月の1行を書き込む（既存行は上書き、無ければ追記）。`KPI評価` と `品種別集約` で使用 |
| `ensureMonthlySummary(monthlySummary, ym)` | 復元用サマリーに対象年月の入れ物を用意する |
| `formatDateCell(val)` | セルの日付値を `YYYY/MM/DD` の文字列に揃える |

- 大量書き込み時のパフォーマンスのため、2次元配列による一括書き込み（`setValues`）を使用している。
