# 03. データ設計書 - 工場エネルギー（電力）使用量集計システム

## 1. スプレッドシート構成

本システムが連携するGoogleスプレッドシートは以下のシートで構成される。シート名は `gas_app/Config.gs` の `CONFIG.SHEET_NAMES` で定義している。

| シート名 | 用途 | レコード単位 | 主キー / 照合キー | アプリからの利用 |
|---|---|---|---|---|
| `1時間集計(ALL)` | 全90系統の1時間平均電力量（kWh）および操業時間の蓄積 | 1時間（1行） | `日時キー` (YYYY/MM/DD HH:00) | 書き込みのみ |
| `日別集約` | カテゴリ別小計および操業時間の1日合計値 | 1日（1行） | `年月日` (YYYY/MM/DD) | 書き込み・起動時の復元・エクスポート |
| `KPI評価` | 月次の総電力・原単位・コスト評価の記録 | 1ヶ月（1行） | `対象年月` (YYYYMM) | 書き込み・起動時の復元・エクスポート |
| `品種別集約` | 8品種別の生産本数・電力量・操業時間（実充填／水運転） | 1ヶ月（1行） | `対象年月` (YYYYMM) | 書き込み・起動時の復元・エクスポート |

いずれも1行目がヘッダーで、`setupSheets()` が自動で作成する。

### 書き込み方式
- **`1時間集計(ALL)`・`日別集約`**: A列が対象年月（`YYYY/MM/`）で始まる最初の行を探し、あればその行から1か月分をまとめて上書きする。無ければ末尾に追記する。同じ月の行が連続して並び、行数が変わらないことを前提としているため、シート上で行の並べ替えや削除を行うと、上書き位置がずれる。
- **`KPI評価`・`品種別集約`**: A列の対象年月が一致する行を上書きする。無ければ末尾に追記する。

## 3. `日別集約`・`KPI評価`・`品種別集約` シート カラム設計

### 3.1 `日別集約`（16列）
`年月日`、`日`、11カテゴリの電力量（`総電力 (kWh)`、`ユーティリティ (kWh)`、`コンプレッサー (kWh)`、`ボイラー (kWh)`、`純水装置 (kWh)`、`排水処理 (kWh)`、`チラー (kWh)`、`調合抽出 (kWh)`、`供給 (kWh)`、`充填 (kWh)`、`包装 (kWh)`）、`水運転(分)`、`実充填(分)`、`合計操業時間(分)`。

### 3.2 `KPI評価`（8列）
`対象年月`、`総電力量(kWh)`、`操業時間(分)`、`生産本数(本)`、`時間原単位(kWh/分)`、`本原単位(kWh/本)`、`1本当たりコスト(円)`、`電力量単価(円/kWh)`。

保存するのは操業モード「水運転＋実充填」の値のみ。

### 3.3 `品種別集約`（41列）
`対象年月` に続けて、8品種（`2.0L`、`1.5L`、`1.0L`、`600mL丸`、`500mL丸`、`500mL角`、`350mL`、`280mL`）それぞれについて、次の5項目を項目ごとに8列ずつ並べる。

| 列の並び | 項目 | 出典 |
|:---:|---|---|
| 2〜9 | 生産本数 `(本)` | 月報PET |
| 10〜17 | `実充填(kWh)` | ロガーデータの品種別集計 |
| 18〜25 | `水運転(kWh)` | 同上 |
| 26〜33 | `実充填(分)` | 同上 |
| 34〜41 | `水運転(分)` | 同上 |

過去の25列形式（本数・電力量・操業時間の3項目）で保存された行も読み込める。その場合、電力量と操業時間は実充填の値として扱い、水運転は 0 とする。

## 6. 入力ファイル設計

### 6.1 電力ロガーデータ（TXT / CSV）
- **ファイル名**: `AQyyyymmdd_00N.TXT`（N = 2, 4, 5, 6, 7 がタグ番号）。1日・1タグにつき1ファイル。
- **形式**: カンマ区切り、全項目ダブルクォート付き。文字コードは UTF-8（BOM付き可）のみ対応。
- **構成**: 先頭に `収集タグNo.`、`名称`、`単位` などのヘッダー行があり、その後に1分ごとのデータ行（1列目が日付 `YYYY/M/D`、2列目が時刻 `HH:MM:SS`）が続く。
- **取り込む列**: `単位` が `kW` の列だけを、出現順に設備列へ割り当てる。電流（A）や積算電力量（kWh）の列は使わない。

| タグ | 内容 | 取り込む列 |
|:---:|---|---|
| tag02 | 品種・工程 | `品種` 列、`ステップ` 列 |
| tag04 | コンプレッサー | kW 3列 → D〜F |
| tag05 | 1F動力盤 | kW 28列 → G〜L、N〜AI |
| tag06 | 2F動力・電灯盤 | kW 先頭44列 → AJ〜CA |
| tag07 | 抽出・充填盤 | kW 13列 → CC〜CO |

### 6.2 月報PET（生産実績データ）
- **判別**: ファイル名に `月報` または `pet` を含む Excel。
- **対象シート**: シート名に対象年度（例: `2024`）を含むシート（例: `月報PET(2024）`）。年度は4月〜翌3月で判定する（2024年1月は2023年度）。対象年度のシートが無い場合は、他のシートでは代用せず、その月の本数は 0（なし）とする。
- **レイアウト**: 月ごとに12列幅のブロックが横に並ぶ（4月がB列始まり、5月がN列始まり…）。
- **取得項目**:
  - 月間総生産本数: 先頭10行のうち、ラベルが `実績(本` または `本数` を含むセルの右隣。
  - 読み取るのは対象月のブロック内だけ。ブロック内に値が無い（未入力の）月は、本数 0 とする。
  - 品種別本数: 11行目以降の品種見出しを `VARIETY_MAPPING`（品種合算マッピング）と照合し、見出しの下7行以内にある `充填本数` を採用する。充填本数が空欄または 0 の場合は `入数 × 実績(C/S)` で算出する。
- **品種合算マッピング**: 見出しの文字列は全角・半角を正規化（NFKC）し、空白を除いたうえで、マッピングのキーワードを含むかどうかで判定する。マッピングは `Config.gs` の `VARIETY_MAPPING` で変更でき、アプリ起動時にブラウザ側へ反映される。

### 6.3 エネルギー計算表（電気料金データ）
- **判別**: ファイル名に `エネルギー`、`かつらぎ`、`energy` のいずれかを含む Excel。
- **対象シート**: シート名が対象年度と完全一致するシート（例: `2024`）。無ければ年度の数字を含むシート。対象年度のシートが無い場合は、他のシート（`年度推移_予測用…` など）では代用せず、値なしとする。
- **月の列**: 4月がC列、以降1か月ごとに右へ1列。
- **取得項目**:
  - 使用電力量（千kWh）: `使用電力` を含み、`昼間`・`夜間` を含まない行。
  - 金額（千円）: `使用量（千円）` または `請求金額` を含む行。
  - **電力量単価（円/kWh）**: `金額（千円） ÷ 使用電力量（千kWh）`。
- 対象年度のシートが無い場合や、対象月の値が空欄の場合は、既定の単価（21.4423 円/kWh。2025年3月度の実績値）を使う。

### 6.4 Excelから値を取得できなかった月の扱い
| 状況 | 本数（月報PET） | 電力量単価（エネルギー計算表） |
|---|---|---|
| その種類の Excel が読み込まれていて、対象年度のシートが無い、または対象月が未入力 | 0（なし） | 既定の単価 |
| その種類の Excel が読み込まれていない | その月の既存の値（スプレッドシートから復元した値を含む）を引き継ぐ。無ければ 0 | その月の既存の値を引き継ぐ。無ければ既定の単価 |

- Excel が読み込まれているのに取得できなかった月は、読込後に画面へ警告を表示する（例:「月報PETに 2023年度 のシートが無いため、12ヶ月分（2023年4月〜2024年3月）の本数を取得できませんでした」）。集計とスプレッドシートへの反映はそのまま行える。
- 月報PET・エネルギー計算表の片方だけを投入しても、もう片方に由来する値（本数または単価）は変わらない。
