# 03. データ設計書 - 工場エネルギー（電力・燃料・トータルエネルギー）使用量集計システム

## 1. スプレッドシート構成

本システムが連携するGoogleスプレッドシートは以下のシートで構成される。シート名は `gas_app/Config.gs` の `CONFIG.SHEET_NAMES` で定義している。

| シート名 | 用途 | レコード単位 | 主キー / 照合キー | アプリからの利用 |
|---|---|---|---|---|
| `1時間集計(ALL)` | 全90系統の1時間平均電力量（kWh）および操業時間の蓄積 | 1時間（1行） | `日時キー` (YYYY/MM/DD HH:00) | 書き込みのみ |
| `日別集約` | カテゴリ別小計および操業時間の1日合計値 | 1日（1行） | `年月日` (YYYY/MM/DD) | 書き込み・起動時の復元・エクスポート |
| `KPI評価` | 月次の総電力・原単位・コスト評価の記録 | 1ヶ月（1行） | `対象年月` (YYYYMM) | 書き込み・起動時の復元・エクスポート |
| `品種別集約` | 8品種別の生産本数・電力量・操業時間（実充填／水運転） | 1ヶ月（1行） | `対象年月` (YYYYMM) | 書き込み・起動時の復元・エクスポート |
| `燃料集約` | 燃料（A重油・LNG）の熱量・購入費用と、8品種別の本数 | 1ヶ月（1行） | `対象年月` (YYYYMM) | 書き込み・起動時の復元・エクスポート（燃料エネルギーの画面） |
| `トータルエネルギー集約` | 生産数量、A重油・LNG・電気の熱量と CO2、原油換算量、太陽光発電 | 1ヶ月（1行） | `対象年月` (YYYYMM) | 書き込み・起動時の復元・エクスポート（トータルエネルギーの画面） |

いずれも1行目がヘッダーで、`setupSheets()` が自動で作成する。

### 書き込み方式
- **`1時間集計(ALL)`・`日別集約`**: A列が対象年月（`YYYY/MM/`）で始まる最初の行を探し、あればその行から1か月分をまとめて上書きする。無ければ末尾に追記する。同じ月の行が連続して並び、行数が変わらないことを前提としているため、シート上で行の並べ替えや削除を行うと、上書き位置がずれる。
- **`KPI評価`・`品種別集約`**: A列の対象年月が一致する行を上書きする。無ければ末尾に追記する。
- **`燃料集約`・`トータルエネルギー集約`**: 同じく、A列の対象年月が一致する行を上書きし、無ければ末尾に追記する。複数月を1回の呼び出しでまとめて書き込む。

## 3. `日別集約`・`KPI評価`・`品種別集約` シート カラム設計

### 3.1 `日別集約`（16列）
`年月日`、`日`、11カテゴリの電力量（`総電力 (kWh)`、`ユーティリティ (kWh)`、`コンプレッサー (kWh)`、`ボイラー (kWh)`、`純水装置 (kWh)`、`排水処理 (kWh)`、`チラー (kWh)`、`調合抽出 (kWh)`、`供給 (kWh)`、`充填 (kWh)`、`包装 (kWh)`）、`水運転(分)`、`実充填(分)`、`合計操業時間(分)`。

### 3.2 `KPI評価`（8列）
`対象年月`、`総電力量(kWh)`、`操業時間(分)`、`生産本数(本)`、`時間原単位(kWh/分)`、`本原単位(kWh/本)`、`1本当たりコスト(円)`、`電力量単価(円/kWh)`。

保存するのは操業モード「水運転＋実充填」の値のみ。

### 3.3 `品種別集約`（41列）
`対象年月` に続けて、8品種（`2.0L`、`1.5L`、`1.0L`、`600mL丸`、`500mL丸`、`500mL角`、`350mL`、`280mL`）それぞれについて、次の5項目を項目ごとに8列ずつ並べる。

| 列の並び | 項目 | 出典 |
|:---:|---|---|
| 2〜9 | 生産本数 `(本)` | 月報PET |
| 10〜17 | `実充填(kWh)` | ロガーデータの品種別集計 |
| 18〜25 | `水運転(kWh)` | 同上 |
| 26〜33 | `実充填(分)` | 同上 |
| 34〜41 | `水運転(分)` | 同上 |

過去の25列形式（本数・電力量・操業時間の3項目）で保存された行も読み込める。その場合、電力量と操業時間は実充填の値として扱い、水運転は 0 とする。

### 3.4 `燃料集約`（13列）
燃料エネルギーの画面が使う入力値を、月1行で保存する。按分後の品種別の値や原単位は保存せず、表示のたびに計算する（計算式は `docs/04_実装仕様.md` の 2.6）。

| 列 | 項目 | 出典 |
|:---:|---|---|
| 1 | `対象年月` (YYYYMM) | - |
| 2 | `A重油 熱量(GJ)` | エネルギー計算表 |
| 3 | `LNG 熱量(GJ)` | 同上 |
| 4 | `A重油 購入費用(千円)` | 同上 |
| 5 | `LNG 購入費用(千円)` | 同上 |
| 6〜13 | 8品種（`2.0L`、`1.5L`、`1.0L`、`600mL丸`、`500mL丸`、`500mL角`、`350mL`、`280mL`）の本数 `(本)` | 月報PET |

- 品種別の本数が無い月（月報PETに対象年度のシートが無い、または未入力）は、6〜13列を空欄にする。空欄は「本数なし」、0 は「その品種の生産なし」を表す。
- 値が無い燃料の項目（LNG を使っていない年度の LNG 購入費用など）も空欄にする。
- 品種別の操業時間は保存しない。電力側の `品種別集約` シートの値（実充填(分)＋水運転(分)）を使う。
- 保存されるのは、表示する年度（月報PETに年度のシートがある年度）の月だけ。それ以外の年度の行がシートにあっても画面には表示されず、アプリが削除することもない。

### 3.5 `トータルエネルギー集約`（16列）
トータルエネルギーの画面が使う、エネルギー計算表から読んだ値を、月1行で保存する。原単位などの比、累計、年間計、前年度比は保存せず、表示のたびに計算する（計算式は `docs/04_実装仕様.md` の 2.7）。列の定義は `Config.gs` と `js/config.js` の `TOTAL_ENERGY_SHEET_COLUMNS` にある。

| 列 | 項目 | 月次データの項目名 |
|:---:|---|---|
| 1 | `対象年月` (YYYYMM) | - |
| 2 | `生産数量(ケース)` | `productionCases` |
| 3 | `1ケースあたりの容量(L)` | `litersPerCase` |
| 4〜7 | `A重油 熱量(GJ)`、`LNG 熱量(GJ)`、`電気 熱量(GJ)`、`合計 熱量(GJ)` | `heavyOilGj`、`lngGj`、`electricityGj`、`totalGj` |
| 8 | `原油換算量(kl)` | `crudeOilKl` |
| 9〜12 | `A重油 CO2(t-CO2)`、`LNG CO2(t-CO2)`、`電気 CO2(t-CO2)`、`合計 CO2(t-CO2)` | `heavyOilCo2`、`lngCo2`、`electricityCo2`、`totalCo2` |
| 13〜15 | `太陽光 発電量(千kWh)`、`太陽光 熱量(GJ)`、`太陽光 CO2(t-CO2)` | `solarKwhThousand`、`solarGj`、`solarCo2` |
| 16 | `原油換算量 太陽光無し想定(kl)` | `noSolarCrudeOilKl` |

- 値が無い項目は空欄にする（太陽光の行が無い年度の 13〜16列など）。空欄は「値なし」、0 は「0」を表す。
- 保存されるのは、表示する年度（月報PETに年度のシートがある年度）の月だけ。

## 6. 入力ファイル設計

### 6.1 電力ロガーデータ（TXT / CSV）
- **ファイル名**: `AQyyyymmdd_00N.TXT`（N = 2, 4, 5, 6, 7 がタグ番号）。1日・1タグにつき1ファイル。
- **形式**: カンマ区切り、全項目ダブルクォート付き。文字コードは UTF-8（BOM付き可）のみ対応。
- **構成**: 先頭に `収集タグNo.`、`名称`、`単位` などのヘッダー行があり、その後に1分ごとのデータ行（1列目が日付 `YYYY/M/D`、2列目が時刻 `HH:MM:SS`）が続く。
- **取り込む列**: `単位` が `kW` の列だけを、出現順に設備列へ割り当てる。電流（A）や積算電力量（kWh）の列は使わない。

| タグ | 内容 | 取り込む列 |
|:---:|---|---|
| tag02 | 品種・工程 | `品種` 列、`ステップ` 列 |
| tag04 | コンプレッサー | kW 3列 → D〜F |
| tag05 | 1F動力盤 | kW 28列 → G〜L、N〜AI |
| tag06 | 2F動力・電灯盤 | kW 先頭44列 → AJ〜CA |
| tag07 | 抽出・充填盤 | kW 13列 → CC〜CO |

### 6.2 月報PET（生産実績データ）
- **判別**: ファイル名に `月報` または `pet` を含む Excel。
- **対象シート**: シート名に対象年度（例: `2024`）を含むシート（例: `月報PET(2024）`）。年度は4月〜翌3月で判定する（2024年1月は2023年度）。対象年度のシートが無い場合は、他のシートでは代用せず、その月の本数は 0（なし）とする。
- **レイアウト**: 月ごとに12列幅のブロックが横に並ぶ（4月がB列始まり、5月がN列始まり…）。
- **取得項目**:
  - 月間総生産本数: 先頭10行のうち、ラベルが `実績(本` または `本数` を含むセルの右隣。
  - 読み取るのは対象月のブロック内だけ。ブロック内に値が無い（未入力の）月は、本数 0 とする。
  - 品種別本数: 11行目以降の品種見出しを `VARIETY_MAPPING`（品種合算マッピング）と照合し、見出しの下7行以内にある `充填本数` を採用する。充填本数が空欄または 0 の場合は `入数 × 実績(C/S)` で算出する。
- **品種合算マッピング**: 見出しの文字列は全角・半角を正規化（NFKC）し、空白を除いたうえで、マッピングのキーワードを含むかどうかで判定する。マッピングは `Config.gs` の `VARIETY_MAPPING` で変更でき、アプリ起動時にブラウザ側へ反映される。

### 6.3 エネルギー計算表（電気料金データ）
- **判別**: ファイル名に `エネルギー`、`かつらぎ`、`energy` のいずれかを含む Excel。
- **対象シート**: シート名が対象年度と完全一致するシート（例: `2024`）。無ければ年度の数字を含むシート。対象年度のシートが無い場合は、他のシート（`年度推移_予測用…` など）では代用せず、値なしとする。
- **月の列**: 4月がC列、以降1か月ごとに右へ1列。
- **取得項目**:
  - 使用電力量（千kWh）: `使用電力` を含み、`昼間`・`夜間` を含まない行。
  - 金額（千円）: `使用量（千円）` または `請求金額` を含む行。
  - **電力量単価（円/kWh）**: `金額（千円） ÷ 使用電力量（千kWh）`。
- 対象年度のシートが無い場合や、対象月の値が空欄の場合は、既定の単価（21.4423 円/kWh。2025年3月度の実績値）を使う。

### 6.4 Excelから値を取得できなかった月の扱い
| 状況 | 本数（月報PET） | 電力量単価（エネルギー計算表） |
|---|---|---|
| その種類の Excel が読み込まれていて、対象年度のシートが無い、または対象月が未入力 | 0（なし） | 既定の単価 |
| その種類の Excel が読み込まれていない | その月の既存の値（スプレッドシートから復元した値を含む）を引き継ぐ。無ければ 0 | その月の既存の値を引き継ぐ。無ければ既定の単価 |

- Excel が読み込まれているのに取得できなかった月は、読込後に画面へ警告を表示する（例:「月報PETに 2023年度 のシートが無いため、12ヶ月分（2023年4月〜2024年3月）の本数を取得できませんでした」）。集計とスプレッドシートへの反映はそのまま行える。
- 月報PET・エネルギー計算表の片方だけを投入しても、もう片方に由来する値（本数または単価）は変わらない。

### 6.5 エネルギー計算表（燃料データ）
燃料エネルギーの画面は、電力と同じエネルギー計算表から、燃料の値を読む。

- **対象シート**: 表示する年度（月報PETに年度のシートがある年度。`docs/01_要件定義書.md` の 3.9）のシートだけを読む。シートの選び方は 6.3 と同じ。
- **月の列**: 月見出しの行（C列から12列に、その年度の4月〜翌3月の日付が並ぶ行）を探し、その行より下を読む。月の列の位置は 6.3 と同じ。
- **取得項目**: A列の `A重油`・`LNG`・`使用電力` を区切りとして区間を分け、それぞれの区間の中で次の行を読む。行の位置は年度によって違うため、固定の行番号は使わない。

  | 燃料 | 熱量 | 費用 |
  |---|---|---|
  | A重油 | B列が `熱量GJ` の行 | B列が `購入費用（千円）` で始まる行 |
  | LNG | B列が `熱量GJ` の行 | B列が `購入費用（千円）` で始まる行 |

  - ラベルは全角・半角を正規化（NFKC）し、空白を除いて比べる。
  - `A重油(本社）` の費用や、電気・太陽光の `熱量GJ` は読まない。
- **対象になる月**: A重油と LNG の熱量の合計が 0 より大きい月。未入力の月は対象外。
- **読めない年度**: A重油の熱量・費用、LNG の熱量のいずれかの行が見つからない年度は読めない。LNG の費用の行だけが無い場合は、LNG の熱量がすべて 0 の年度（LNG を使っていない年度）に限り、費用なしとして読む。表示する年度の中に読めない年度があれば、画面に警告を表示する。
  - エネルギー計算表の 2016・2017年度のシートは、LNG を使っているのに費用の行が無いため読めない（2026年10月時点の月報PETにはこの年度のシートが無いため、表示する年度には含まれない）。
- **費用の扱い**: 費用は購入した月に計上される値（熱量は使用した月の値）。そのため、月ごとの燃料単価（費用 ÷ 熱量）は月によって大きく変わり、購入の無い月は費用が 0 になる。

### 6.6 燃料エネルギーで使う月報PETの値
- 8品種別の本数（6.2 の「品種別本数」）を使う。月の生産本数は、8品種の本数の合計とする（電力の画面が使う `実績（本)` の値とは一致しないことがある）。
- 月報PETに年度のシートがある年度だけが、表示・保存の対象になる。その年度の中で、8品種の本数がひとつも取得できない月（未入力の月）は、「本数なし」として扱う（0 本とは区別する）。
- 月報PETを読み込んでいない場合は、その月の既存の本数（スプレッドシートから復元した値を含む）を引き継ぐ。エネルギー計算表を読み込んでいない場合の燃料の値も同じ。

### 6.7 エネルギー計算表（トータルエネルギーのデータ）
トータルエネルギーの画面は、エネルギー計算表の年度シートから、Excel が計算した月別の値を読む。熱量・CO2・原油換算の係数は年度によって違う（例: 電気の CO2 係数、A重油の熱量）ため、アプリでは再計算しない。

- **対象シート**: 表示する年度（月報PETに年度のシートがある年度）のシート。月の列と月見出しの行の探し方は 6.5 と同じ。
- **取得項目**: 行の位置は年度によって違うため、次のラベルで探す。

  | 項目 | 探し方 |
  |---|---|
  | A重油・LNG の熱量、CO2 | A列の `A重油`・`LNG` の区間で、B列が `熱量GJ`・`t-CO2` の行 |
  | 電気の熱量、CO2 | A列が `使用電力` で始まる行から、`太陽光発電量`（無ければ `合計GJ`）の手前までの区間で、B列が `熱量GJ`・`t-CO2` の行。`熱量GJ（昼間）`・`熱量GJ（夜間）` の行は対象外 |
  | 合計の熱量、CO2、原油換算量 | A列が `合計GJ`・`合計t-CO2`・`合計GJ原油換算量` の行のうち、最初に現れるもの |
  | 生産数量（ケース） | A列が `生産数量` で、B列が `ケース` の行（すぐ下の `千ケース` の行は整数に丸めた値のため使わない） |
  | 1ケースあたりの容量（L） | A列が `PET生産量` の行の B列（全年度 12）。読めない場合は 12 |
  | 太陽光の発電量、熱量、CO2 | A列が `太陽光発電量` で始まる行と、その区間の `熱量GJ`・`t-CO2` の行（2023年度以降のシートにある） |
  | 太陽光無し想定の原油換算量 | 合計の3行のすぐ下にある `太陽光発電 無しの想定値` の欄の `合計GJ原油換算量` の行 |

- **対象になる月**: 合計の熱量（`合計GJ`）が 0 より大きい月。未入力の月は対象外。
- **読めない年度**: 3つの区間、合計の3行、各エネルギー源の熱量の行、生産数量の行のいずれかが見つからない年度は読めない。表示する年度の中にあれば、画面に警告を表示する。CO2 の内訳や太陽光の行が無い場合は、その項目だけ値なしとして読む。
- 2026年10月時点の読込用ファイルでは、2013〜2026年度の全14シートが読める（月別の原単位・1klあたりの CO2 が、シート上の値と全月一致することを確認している）。
- **Excel 側の注意**:
  - シート上部の年間サマリーの「前年」の列は、前年度のシートを参照する式になっているが、2026年度のシートは 2024年度のシートを参照している。アプリの前年度比は、直前の年度（2025年度）と比べる。
  - 2018年度以前のシートの年間サマリーは、生産量や原単位を丸めた値で持っている。アプリは丸めずに計算する。
  - シート内の `累計` の行には、式が崩れている箇所がある（例: 2024年度の3月の `合計t-CO2累計`）。アプリの累計は月別の値から計算する。
  - `生産数(千ケース)あたりのCO2排出量` の月別の値は、Excel では千ケースを整数に丸めてから割っている。アプリは丸めずに計算するため、月別の値がわずかに違う（差は 0.5% 未満）。
