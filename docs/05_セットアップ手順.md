# 05. セットアップ・運用手順書 - 工場エネルギー（電力・燃料・トータルエネルギー）使用量集計システム

## 1. はじめに
本手順書は、「工場エネルギー（電力・燃料・トータルエネルギー）使用量集計システム」をGoogle Apps Script（GAS）およびGoogleスプレッドシート上に構築・デプロイし、日常業務で運用するための手順を説明したものです。

---

## 2. 初回セットアップ手順（管理者向け）

### ステップ 1: 集計用Googleスプレッドシートの作成
1. Googleドライブを開き、新規「Googleスプレッドシート」を作成します。
2. スプレッドシートの名称を「**工場電力使用量集約管理**」等に変更します。
3. ブラウザのアドレスバーに表示されているURLから「**スプレッドシートID**」をコピーします。
   ```
   https://docs.google.com/spreadsheets/d/【ここがスプレッドシートID】/edit
   ```

### ステップ 2: GASプロジェクトの作成とコード配置
1. 作成したスプレッドシートのメニューバーから「**拡張機能**」>「**Apps Script**」をクリックします。
2. プロジェクト名を「**エネルギー使用量集計システム**」に変更します。
3. ローカルの `gas_app/` フォルダ配下のファイルから、**以下の3つのファイルのみ**をApps Scriptエディタに配置します。

| GAS上のファイル名 | 種類 | ローカル対応ファイル | 役割 |
|---|:---:|---|---|
| `Code.gs` | スクリプト | `gas_app/Code.gs` | 画面の配信、スプレッドシートへの保存・復元・エクスポート用データ取得 |
| `Config.gs` | スクリプト | `gas_app/Config.gs` | スプレッドシートID・列定義設定 |
| `index.html` | HTML | `gas_app/index.html` | SPAダッシュボード画面本体（CSS/JS完全内包） |

> **【ポイント】**
> - スタイルシート（CSS）や各機能スクリプト（JS）は、すべて `gas_app/index.html` 内にインライン統合（自己完結型バンドル）されています。
> - そのため、Apps Script側で `css/style.html` や `js/app.html` などの分割ファイルを個別に作成する必要は**一切ありません**。
> - 既に過去の手順で作成した `js/*.html` や `css/*.html` がApps Script上に残っている場合でも、動作には影響ありません（削除して整理しても構いません）。

4. `Config.gs` 内の `SPREADSHEET_ID` に、ステップ1で取得したスプレッドシートIDを貼り付けます（同一スプレッドシートのコンテナバインドスクリプトの場合は空文字のままで自動認識されます）。

### ステップ 3: 初期シートの自動生成
1. Apps Scriptエディタの関数選択プルダウンから `setupSheets` を選択します。
2. 「**実行**」ボタンをクリックします（初回実行時はGoogleアカウントのアクセス承認ダイアログが表示されますので許可してください）。
3. 実行が完了すると、スプレッドシート上に自動的に以下の6シートが作成され、全列ヘッダーが設定されます：
   - `1時間集計(ALL)`（全96列、01分締め集計値・操業時間）
   - `日別集約`（各カテゴリ小計・操業時間）
   - `KPI評価`（総電力量・原単位・コスト評価）
   - `品種別集約`（8品種別の本数・実充填/水運転の電力量と操業時間）
   - `燃料集約`（A重油・LNG の熱量と購入費用、8品種別の本数）
   - `トータルエネルギー集約`（生産数量、A重油・LNG・電気の熱量と CO2、原油換算量、太陽光発電）

> この手順を省略しても、アプリから最初に「スプレッドシートへ反映」を実行したときに、必要なシートが自動で作成されます。

### 既に運用中の環境を更新する場合
`gas_app/` のファイルを変更したときは、Apps Script エディタ上の `Code.gs`・`Config.gs`・`index.html` を新しい内容に貼り替え、「**デプロイ**」>「**デプロイを管理**」から新しいバージョンとして再デプロイします。

- 燃料エネルギー・トータルエネルギーの機能を使うには、3ファイルすべての更新が必要です。`index.html` だけを更新した場合、電力の機能はそのまま使えますが、`Code.gs` に関数が無い画面のデータは保存・復元できません（反映時に「新しい Code.gs のデプロイが必要です」と表示されます）。
- `燃料集約`・`トータルエネルギー集約` シートは、最初にいずれかの画面のデータを反映したときに自動で作成されます。既存のシートの内容は変わりません。
- `燃料集約` シートに、月報PETにシートが無い年度（2023年度以前など）の行が保存済みの場合、その行は画面に表示されなくなります。シートからは削除されず、Excelエクスポートには含まれます。不要であれば、シート上で行を削除してください。

### ステップ 4: Webアプリとしてのデプロイ
1. Apps Scriptエディタ右上の「**デプロイ**」>「**新しいデプロイ**」をクリックします。
2. 種類の選択で「**ウェブアプリ**」を選択します。
3. 以下の通り設定します：
   - **説明**: `工場電力ダッシュボード v1.0`
   - **次のユーザーとして実行**: `自分`
   - **アクセスできるユーザー**: `全員` または `ドメイン内の全員`
4. 「**デプロイ**」をクリックし、発行された「**ウェブアプリのURL**」をコピーして関係者に共有します。

## 3. 開発・検証・ビルド手順（開発者向け）

### 自己完結型 index.html のビルド
`gas_app/css/style.css` や `gas_app/js/*.js`、`gas_app/index.template.html` を編集した後は、以下のコマンドで本番用 `index.html` を再生成します：
```bash
node gas_app/build.js
```
再生成した `index.html`（および変更した `Code.gs`・`Config.gs`）を Apps Script エディタへ貼り替え、「デプロイ」>「デプロイを管理」から新しいバージョンとしてデプロイし直すと、本番へ反映されます。

`Config.gs` と `gas_app/js/config.js` には同じマスター定義（品種キー、品種合算マッピング、カテゴリ、設備90列、目盛り設定）があります。どちらかを変更したら、もう一方も同じ内容に揃えてください。

### ローカルでの動作確認
GASにデプロイせずに画面を確認できます。
```bash
cd gas_app
python3 -m http.server 8000
```
ブラウザで `http://localhost:8000/index.html` を開きます。
- `localhost`（または `127.0.0.1`）で開いた場合のみ、ヘッダーにデモデータの読込ボタン（「年間デモ再読込」「単月デモ」）が表示され、起動時に `gas_app/demo/` の年間デモデータを自動で読み込みます。
- 実際のロガーファイルや Excel をドロップして集計することもできます。
- `http://localhost:8000/index.html?app=fuel` で開くと燃料エネルギーの画面、`?app=total` で開くとトータルエネルギーの画面を表示した状態で起動します。
- ローカルではスプレッドシートに接続しないため、「スプレッドシートへ反映」は成功を返すだけで保存されません。「Excelエクスポート」はブラウザが保持しているデータから出力します。

### テストの実行
プロジェクトのルートで実行します。`reference/` 配下の実データが必要なものがあります。

| コマンド | 内容 |
|---|---|
| `node tests/test_etl_runner.js` | 2025年3月度の実データ（`reference/読込用データ/CSVデータ/2024年度/202503/`）で集計を実行し、`tests/test_output_202503.json` を出力 |
| `python3 tests/verify_output.py tests/test_output_202503.json` | 上記の出力を正解データ（`tests/truth_202503.json`）と突合 |
| `node tests/verify_variety_fixes.js` | 品種マスター、操業モード別の品種集計の検証 |
| `node tests/verify_variety_and_restore.js` | 復元データからの年間集約の検証 |
| `node tests/verify_config_sync.js` | `Config.gs` と `js/config.js` の定義が一致していることの検証 |
| `node tests/verify_excel_reader.js` | 月報PET・エネルギー計算表の解析の検証（年度のシートが無い場合や未入力の月に、別の値を取り込まないこと。燃料の行の読み取りを含む） |
| `node tests/verify_fuel_service.js` | 燃料エネルギーの集計の検証（品種別按分・8評価項目・累計が、参考 Excel の2024年4・5月の値と一致すること） |
| `node tests/verify_fuel_view.js` | 燃料エネルギー画面のデータ処理の検証（表示する年度の決め方、Excel の取り込みルール、反映済みの判定、目盛り上限） |
| `node tests/verify_total_energy.js` | トータルエネルギーの読み取り・集計・画面のデータ処理の検証（年度シートの行の探し方、原単位・CO2 の比、累計、年間計、前年度比、年度推移） |
| `python3 tests/extract_reference_truth.py` | Excel原紙（`reference/参考用データ/`）から正解データを作り直す（通常は実行不要） |

## 4. 日常の運用手順（現場担当者向け）

### 手順 1: アプリ画面を開く
- 共有されたWebアプリURLをブラウザ（Google Chrome推奨）で開きます。

### 手順 2: ファイルのドラッグ＆ドロップ投入
1. 画面上部のナビゲーションで「**単月詳細集約**」を開きます（ファイルを受け付けるエリアはこの画面にあります）。
2. 集計対象月のロガーファイル（`AQyyyymmdd_00N.TXT`。tag02, tag04, tag05, tag06, tag07 の5種類）を選択します。月のフォルダごとドロップすることもできます。
3. 同時に、「月報PET」および「エネルギー計算表」のExcelファイルも選択します。Excelは後から単独で投入しても、読込済みの全月に反映されます。月報PETに対象年度のシートが無い月や、本数・単価が未入力の月がある場合は、画面に警告が表示されます。
4. 「CSV/TXTファイル または 外部Excelをドラッグ＆ドロップ」エリアに投入します（またはクリックしてファイル選択）。

> **【注意】**
> - 同じ月のファイルは、5種類のタグをまとめて投入してください。一部のタグだけを投入すると、その月は投入したファイルだけで計算し直され、足りないタグの設備は 0 として集計されます。
> - 複数月のファイルを一度に投入すると、ファイル名の年月ごとに自動で分けて集計します。

### 手順 3: 自動集計の確認
- ファイルが解析され、検出したファイル種別のバッジが点灯します。5種類のタグすべてが点灯していることを確認してください。
- KPIカードに月間総電力量、操業時間、電力量単価が表示されます。
- グラフ（日別推移、工程別比率）および集計テーブルが描画されます。
- 年間の推移は「年間推移・品種別分析」「年間推移・設備別分析」の各画面で確認できます。

### 手順 4: スプレッドシートへの反映・保存
- 画面右上の「**スプレッドシートへ反映**」ボタンをクリックします。未反映の月だけが保存されます。
- 保存が終わると、「スプレッドシートへの同期が正常に完了しました」と通知が表示されます。
- 読込済みの全月が反映済みの状態でボタンを押すと、全月を上書きしてよいかの確認が表示されます。
- 必要に応じて「**Excelエクスポート**」をクリックすると、スプレッドシートに保存済みの `日別集約`・`KPI評価`・`品種別集約`・`燃料集約`・`トータルエネルギー集約` の5シートをExcelファイルとしてダウンロードできます（データの無いシートは出力されません）。まだ反映していないデータは含まれないため、先に反映を済ませてください。

次回アプリを開いたときは、スプレッドシートに保存済みのデータが自動で読み込まれます。

### 手順 5: 燃料エネルギーの確認と反映
1. 画面上部の切替ボタンで「**燃料エネルギー**」を選びます。
2. 「エネルギー計算表・月報PET (Excel) をドラッグ＆ドロップ」エリアに、エネルギー計算表と月報PETを投入します。電力の画面（手順 2）で投入済みであれば、あらためて投入する必要はありません。
   - 表示されるのは、月報PETに年度のシートがある年度だけです（エネルギー計算表だけを投入した場合は、月報PETの投入を案内します）。
   - ロガーファイル（TXT/CSV）は、電力の「単月詳細集約」で投入してください。
3. 対象年度と評価項目を選んで、グラフと集計表を確認します。
   - 月報PETで本数が未入力の月は、月計だけが表示され、品種別の値と本数あたりの項目は「---」になります。
   - 操業時間・単位時間燃料エネルギー・単位時間コストは、電力の画面でその月のロガーデータを読み込んでいるか、スプレッドシートに保存済みの月だけ表示されます。
4. 画面右上の「**スプレッドシートへ反映**」ボタンをクリックします。燃料エネルギーを表示しているときは、燃料のデータ（未反映の月と、値が変わった月）が `燃料集約` シートへ保存されます。電力のデータは、電力の画面に切り替えてから反映してください。

### 手順 6: トータルエネルギーの確認と反映
1. 画面上部の切替ボタンで「**トータルエネルギー**」を選びます。
2. エネルギー計算表と月報PETを投入します。他の画面で投入済みであれば、あらためて投入する必要はありません。
   - 値はエネルギー計算表だけで決まります。月報PETは、表示する年度（月報PETに年度のシートがある年度）を決めるために使います。
3. 対象年度を選び、「**月別**」と「**年度推移**」を切り替えて、グラフと集計表を確認します。
   - 月別: 対象年度の4月〜3月の推移と年間計。
   - 年度推移: 各年度の年間値。入力途中の年度は「2026年度 (6ヶ月)」のように月数が付き、総量（生産数量・熱量・CO2排出量）は他の年度より小さく表示されます。
   - 前年度比は、前年度も表示されている場合に表示されます。
   - 太陽光発電のデータがある年度は、下に「参考: 太陽光発電 無しの想定値」の表が表示されます。
4. 画面右上の「**スプレッドシートへ反映**」ボタンをクリックすると、トータルエネルギーのデータ（未反映の月と、値が変わった月）が `トータルエネルギー集約` シートへ保存されます。

> 同期状況の表示と「スプレッドシートへ反映」ボタンは、表示中の画面（電力／燃料エネルギー／トータルエネルギー）のデータを対象にします。「Excelエクスポート」は、どの画面からでも5シートをまとめて出力します。

---

## 5. 複数月・過去数年分の一括登録

過去データをまとめて登録する場合も、手順は日常運用と同じです。複数月分のロガーファイル（またはフォルダ）と Excel を一度にドロップし、集計が終わったら「スプレッドシートへ反映」を実行します。

一度に読み込む量が多いと、ブラウザのメモリを多く使い、集計中は画面が固まったように見えることがあります。動作が重い場合は、数か月ずつに分けて投入してください。

## 6. トラブルシューティング

| 症状 | 原因 | 対処法 |
|---|---|---|
| ファイルを投入してもバッジが点灯しない | ファイルの種類（タグ）を判別できていない | ファイル名が `AQyyyymmdd_00N.TXT` の形式（末尾が `_002`、`_004`、`_005`、`_006`、`_007`）か、ファイル名に `tag02`〜`tag07` が含まれているか確認してください。ファイル名で判別できない場合は、ファイル先頭の `収集タグNo.` の行で判別します。 |
| 投入したのに集計されない・値が 0 になる | 文字コードが UTF-8 以外、または `名称`・`単位` のヘッダー行が無い | ロガーから出力したままの UTF-8 のファイルを投入してください。 |
| 一部の設備の値が 0 になる | その月の一部のタグのファイルが不足している | 5種類のタグのファイルをまとめて投入し直してください。 |
| 「スプレッドシートへ反映」でエラーになる | アクセス権限不足またはシートID未設定 | `Config.gs` のスプレッドシートIDおよび権限設定を確認してください。 |
| 生産本数や原単位（kWh/本）が 0 になる | 月報PETが未投入、または対象年度のシート・対象月の値が無い | 月報PETのExcelをドロップゾーンに投入してください。投入済みの場合は、月報PETに対象年度（4月〜翌3月）のシートがあり、その月の本数が入力されているか確認してください。 |
| 「月報PETに ○○年度 のシートが無いため…本数を取得できませんでした」と警告が出る | 月報PETのファイルに、その年度のシート（シート名に年度の数字を含むもの）が無い | その年度のシートを含む月報PETを投入してください。本数が不要であれば、そのまま反映して構いません（本数 0 として保存されます）。 |
| 電力量単価が実績と違う | エネルギー計算表が未投入、または対象年度のシート・対象月の値が無い | エネルギー計算表のExcelを投入してください。取得できない月は既定の単価（21.4423 円/kWh）で計算され、警告が表示されます。 |
| 反映済みの月が「未反映」に戻った | ロガーファイルを読み直した、または Excel の投入で本数・単価が変わった | 内容を確認のうえ、「スプレッドシートへ反映」で上書きしてください。 |
| Excelエクスポートで「データが存在しません」と表示される | スプレッドシートにまだ何も保存されていない | 先に「スプレッドシートへ反映」を実行してください。 |
| 燃料エネルギー・トータルエネルギーの画面に何も表示されない | エネルギー計算表と月報PETの両方が読み込まれていない（保存済みのデータも無い） | エネルギー計算表と月報PETの両方を投入してください。表示する年度は、月報PETに年度のシートがある年度です。 |
| 燃料エネルギー・トータルエネルギーに、表示したい年度が出てこない | 月報PETに、その年度のシート（シート名に年度の数字を含むもの）が無い | その年度のシートを含む月報PETを投入してください。 |
| 燃料エネルギーで「○○年度 は、燃料の費用の行を特定できないため表示できません」と警告が出る | その年度のシートに、LNG の `購入費用（千円）` の行が無い（LNG の熱量は入力されている） | その年度は表示できません。必要な場合は、エネルギー計算表のその年度のシートに LNG の購入費用の行を追加してください。 |
| トータルエネルギーで「○○年度 は、必要な行を特定できないため表示できません」と警告が出る | その年度のシートで、`合計GJ`・`合計t-CO2`・`合計GJ原油換算量`・`生産数量`（ケース）などの行のラベルが変わっている | エネルギー計算表のその年度のシートの行のラベルを、他の年度と同じにしてください。 |
| 燃料エネルギーで品種別の値や「MJ/本」「円/本」が「---」になる | 月報PETで、対象月の本数が未入力 | 月報PETに本数を入力して、投入し直してください。 |
