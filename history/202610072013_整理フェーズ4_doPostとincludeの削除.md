# 作業履歴: 整理フェーズ4 doPost と include の削除

## 実施日時
2026-10-07 20:13

## 修正理由・背景
- `gas_app/Code.gs` の `doPost()` と `include()` は、リポジトリ内に呼び出し元が無かった。
  - 画面からの保存・復元・エクスポートは `google.script.run` 経由で、`doPost()` を使っていない。
  - `gas_app/index.html` は `build.js` が CSS / JS をインライン統合した生成物で、`<?!= include(...) ?>` を含まない。
- ユーザーに確認し、外部から Web アプリ URL に POST している利用が無い前提で削除した。

## 修正内容
1. **GAS側の未使用関数の削除（`gas_app/Code.gs`）**
   - `include()`、`doPost()`、`doPost()` 専用の `createJsonResponse()` を削除（計89行）。
   - ファイル冒頭の説明コメントを実態に合わせて修正。

2. **テンプレートのスクリプトレットの削除（`gas_app/index.template.html`）**
   - `<?!= include('css/style'); ?>` を含む `<style>` ブロックと、JS 9本分の `<?!= include(...) ?>` を削除。
   - ビルドの置換開始位置になっている `<!-- CSSスタイル -->` と `<!-- スクリプト読み込み` のコメント、およびテンプレートをローカルで直接開いた場合のスクリプト読み込み処理は残した。

3. **ビルドスクリプトのコメント修正（`gas_app/build.js`）**
   - スクリプト読み込み領域の説明を実態に合わせて修正（処理は変更なし）。

## 検証結果
- `node gas_app/build.js` で再生成した `gas_app/index.html` は、フェーズ3時点と完全一致（差分なし）。
- `Code.gs` / `Config.gs` の構文チェック: OK。`include(`、`doPost`、`createJsonResponse`、`LockService`、`<?` の残存参照なし。
- テスト一式（`test_etl_runner.js` → `verify_output.py`、`verify_variety_fixes.js`、`verify_variety_and_restore.js`、`verify_config_sync.js`）: PASSED

## 補足
- 作業中、テンプレートのコメントに `</body>` という文字列を書いたため、ビルドの置換範囲が途中で切れて `index.html` に余分なスクリプトが残る状態になった。再ビルド後の差分比較で検出し、コメントから該当文字列を除いて解消した。テンプレートの「スクリプト読み込み」コメントから実際の body 終了タグまでの間には、`</body>` という文字列を書かないこと。
- 排他ロック（`LockService`）は `doPost()` の中にしか無く、画面からの保存処理（`saveAggregatedData`）には元々かかっていなかったため、保存処理の動作は変わらない。
- 本番へ反映するには、`Code.gs`、`Config.gs`、`index.html` を GAS エディタへ貼り替えて再デプロイする必要がある。
